## 데이터베이스와 DBMS
- 데이터베이스 : 데이터의 집합, 형식을 갖추지 않아도 됨
- DBMS : 데이터를 효과적으로 관리하기 위한 시스템, 각각 파일보다 시스템적으로 작동하게 만든 시스템, 

### 관계형 데이터베이스 구성요소 
- 계정 : 데이터 접근 제한을 위한 여러 업무/시스템 별 계정이 존재해야한다
- 테이블 : DBMS의 DB안에 데이터가 저장되는 형식
- 스키마 : 테이블이 어떤 구성으로 되어있는지, 어떤 정보를 가지고 있는지에 대한 기본적인 구조를 정의 

### 테이블 
테이블은 데이터의 저장단위로 행과 열을 가지는 2차원 구조 

- 하나의 테이블은 반드시 하나의 유저 소유여야 한다. 여러 소유자가 하나의 테이블을 소유할 수 없다. 
- 테이블간 관계는 1:1, 1:N, N:M의 관계를 가진다 
- 테이블 명은 중복될 수 있다, 하지만 소유자가 다를경우에는 같은 이름으로 생성할 수 있다
- 데이터는 행 단위로 입력되고 삭제된다. 수정의 값의 단위로 가능 

### 관계형 데이터베이스의 특징
- 데이터의 분류, 정렬, 탐색하는 속도가 빠르다
- 신뢰성이 높다
- 데이터 무결성을 보장한다
- 기존의 작성된 스키마를 수정하기 어렵다
- 데이터베이스의 부하를 분석하는 것이 어렵다

### 데이터무결성(Integrity)
데이터에 결점이 없다는 의미
데이터의 `정확성`과 `일관성`을 유지하고 데이터에 결손과 부정합이 없음을 보증하는 성질
데이터베이스에 저장된 값과 그것이 표현하는 현실의 비즈니스 모델의 값이 일치 

데이터무결성의 종류
- 개체 무결성 :
	- 테이블의 기본키를 구성하는 컬럼은 Null이나 중복값을 가질 수 없다.
	- id = 1인 회원이 있는데 또 id = 1불가능, id = null 불가능
- 참조 무결성 : 
	- 외래키는 실제 참조 대상이 있어야함
	- 외래키 값은 Nul이거나 참조 테이블의 기본키 값과 동일해야 한다
	- member_id = 999인데, 회원.id = 999 없음 -> 저장불가 
- 도메인 무결성 : 
	- 주어진 속성 값이 정의된 도메인에 속한 값이어야 함
	- 나이는 0 이상 정수, 등급은 VIP, NORMAL 등등 규칙을 따라야함
- NULL 무결성 : 
	- 특정 속성에 대해 Null을 허용하지 않는 특징을 가질 수 있다
	- 
- 고유 무결성 : 
	- 특정 속성에 대해 값이 중복되지 않는 특징을 가질 수 있다
	- email, 사용자 id 등
- 키 무결성 : 
	- 하나의 관계에 적어도 하나의 키가 존재해야 한다. (조인키)
	- 각 행을 구별할 수 있는 키가 최소 하나 필요 

## SQL
관계형 DB에서 데이터 조회, 조작과 DBMS 시스템 관리 기능 명령 언어 

### 구분 
- 데이터 정의 DDL 
- 데이터 조작 DML 
- 데이터 제어 DCL

### DDL(Data Definition Language)
- CREATE
- ALTER
- DROP
- TRUNCATE
==구조 자체를 변동, 취소 불가능 (AUTO COMMIT)==
*TRUNCATE는 데이터 구조는 지우지 않지만, 데이터를 모두 지우는 명령어로 취소 불가능한 AUTO COMMIT이기 때문에 DDL* 

### DML (Data Mainpulation Language)

- DELETE
- UPDATE
- MERGE
데이터를 변경

### DCL(Data Control Language)
- GRANT
- REVOKE
데이터에 대한 권한 제어 

### TCL(Transaction Control Language)
- COMMIT
- ROLLBACK
트랜잭션 제어 

### DQL(Data Quert Language)
- SELECT 

### SELECT 문
```SQL
select * 
from 
where
group by
having
order by
```

내부 파싱 순서는 작성 순서와 다르게 
FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY 순서로 실행 

특징 
- SELECT 절에서 표시할 대상 컬럼에 별칭 (Alias)을 지정할 수 있음
- 대소문자를 구분하지 않아도 됨 

별칭(Alias)
- 컬럼명 대신 출력할 임시 이름 지정, *원본 컬럼명은 변경X*
- 컬럼명 뒤에 `AS`와 함께 컬럼의 별칭 작성하면 됨 (생략 가능)
- SELECT 문보다 늦게 수행되는 Order By 절에서만 별칭을 사용할 수 있다 
	```SQL
	SELECT salary * 12 AS annual_salary
FROM employee
ORDER BY annual_salary;
	```
	-  select 에서 만든 별칙 annual_salary는 order by에서 사용 가능 
- 이미 존재하는 예약어는 사용 X 
- 별칭에 공백을 포함하거나, 특수문자를 포함하거나 (언더 바 제외), 별칭 그대로 전달할 경우 " "를 작성해야 함

#### FROM절
데이터를 불러올 테이블명 또는 뷰명을 작성
- 뷰 : 
	- 테이블의 일부를 볼 수 있는 미리보기 
	- 테이블과 동일하게 데이터를 조회할 수 있는 객체지만, 실제 저장된건 X 
- 불러올 테이블 명을 여러개 전달 가능하여 `,`로 구분, ==조인 조건 없이 테이블명만 나열하게 되면 카타시안 곱 발생== 
- 테이블 별칭 선언 가능, oracle은 AS 사용 불가, SQL Server는 사용 및 생략 가능 
	- 테이블 별칭 선언 시 컬럼은 모두 테이블 별칭으로 작성
- 데이터 조회 목적이 아닌 경우 FROM절이 필요없을 수 있지만, Oracle에서는 from 절 생략 불가능하기에 `DUAL` 테이블 선언해야 한다
	- `select 1 + 2 from DUAL;`

#### WHERE 절 
- 필터링을 위해 조건을 작성하는 절 
- 여러 조건 동시 전달 가능 (and, or)
- null 조회 시 is null / is not null 연산자를 사용해야 함
- 문자나 날짜 상수 표현 시에는  ' '을 사용해아 함
- oracle은 문자 상수의 경우 대소문자 구분
- MYSQL은 문자 상수의 대소문자를 구분하지 않음

**IN 연산자** : 
- 포함연산자로 여러 상수와 일치하는 조건을 전달할 때 사용 
- 상수는 괄호로 묶어 동시에 전달한다 

**BETWEEN A AND B** :
- 이상, 이하로 생각 
- 숫자뿐만 아니라 문자, 날짜도 대소비교 가능 

**LIKE :** 정확하게 일치하지 않아도 되는 패턴 조건 전달 
- % : 자리수 제한 없는 모든 의미 
- `_:_` 하나당 자리수 의미 
	- like 'S%': S로 시작하는, S 한 글자여도 가능
	- like '%S%' : S를 포함하는 좌우로 
	- like '%S' : S로 끝나는
	- like '_S%' : 두번째 글짜가 S
	- like `'__S__'`: 가운데 글자가 S인 경우 

**NOT** : 조건 결과의 반대집합
#### GROUP BY 절
- 각 행을 특정 조건에 따라 그룹을 분리하여 계산하도록 하는 구문식
- 여러 컬럼을 전달 가능하다 
- 만약 그룹 연산에서 제외할 대상이 있따면 미리 WHERE 절에서 해당 행을 제외하면 된다 
- 그룹에 대한 조건은 WHERE 절에서 사용할 수 없음
- GROUP BY 절을 사용하면 데이터가 요약
