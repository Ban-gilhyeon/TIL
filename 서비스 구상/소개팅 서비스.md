# 소개팅 서비스

## 한 줄 정의

안전한 사람을 보증하는 앱이 아니라, 모르는 사람을 더 안전하게 만나고 진지한 관계를 시작하도록 돕는 소개팅 서비스.

## 배경

기존 소개팅 서비스는 사진, 직업, 회사, 학교 등 많은 정보를 제공하지만 다음 불확실성을 충분히 없애지 못한다.

- 실제 본인이 맞는가?
- 프로필과 실제 모습이 일치하는가?
- 어떤 의도로 서비스를 이용하는가?
- 실제 만남은 안전한가?
- 문제 발생 시 서비스가 어떤 도움을 제공하는가?

목표는 단순한 매칭률 향상이 아니다. 낯선 사람과 관계를 시작하는 과정의 불확실성과 위험을 줄이는 것이다.

## Product Principles

### Trust

검증 가능한 사실을 확인해 사용자의 판단 근거를 만든다.

- 휴대폰 본인·성인 인증
- 얼굴 및 Liveness 인증
- 프로필 사진과 실제 얼굴 일치 확인
- 선택적 직장·학교 인증
- 휴면 프로필 관리

신원 인증은 행동의 안전성을 보증하지 않는다. 활동 이력이 없다는 이유로 신규 사용자를 위험하게 보거나 추천에서 불리하게 만들지 않는다.

### Safety

사용자를 안전한 사람으로 판정하지 않는다. 만남 전·중·후 과정의 위험을 줄인다.

- 만남 전: 앱 내 채팅, 위험 행동 탐지, 신고 및 증거 보존
- 만남 중: `Meeting`, Safety Check, Trusted Contact
- 만남 후: 별점 대신 구체적인 Safety Event 수집

긍정 평판 점수 대신 반복 신고, 노쇼, 거절 후 접근, 부적절 메시지, 차단 회피 같은 부정적 Risk Signal을 탐지한다.

### Intentional Dating

무한 Swipe와 가벼운 만남보다 진지한 관계 형성을 지원한다.

- 제한된 수의 상세 추천
- 가입 시 관계 목적 명확화
- 매칭 수보다 한 사람을 제대로 알아가는 경험 중시
- 연애 시작 시 Couple Verification 후 서비스 졸업

## 핵심 경험

```text
가입 → 신원 인증 → 제한된 추천 → 매칭 → 앱 내 대화
→ 만남 제안 및 상호 동의 → Meeting 생성
→ Safety Check → 만남 후기/Safety Event
→ 연애 시작 → Couple Verification → 서비스 졸업
```

## 레퍼런스 앱

추후 각 앱의 장점, 한계, 본 서비스에 적용할 요소를 별도로 조사한다.

- Tinder: Swipe 중심 탐색 구조 비교
- Bumble: 여성 주도 대화 시작 및 Safety UX 참고
- Hinge: 상세 프로필과 진지한 관계 포지셔닝 참고
- Coffee Meets Bagel: 제한된 일일 추천 방식 참고
- Noondate: 국내 일일 추천형 소개팅 경험 참고
- Amanda: 국내 가입 심사와 인증 구조의 장단점 비교

## 차별화 도메인

- `Meeting`: 실제 만남 일정과 Safety 기능 관리
- `Safety Check`: 도착·진행 상태 확인과 도움 메뉴 제공
- `Risk Signal`: 확인된 위험 징후 관리
- `Moderation`: 증거 검토, 제재, 이의 제기 관리
- `Couple`: 상호 연애 확인과 서비스 졸업 관리

일반 도메인 후보: `User`, `Identity`, `Profile`, `Recommendation`, `Matching`, `Chat`, `Report`, `Block`, `Notification`.

## 운영 원칙

- 신고는 주장, Risk Signal은 검토 결과로 분리한다.
- 신고 한 번만으로 위험 사용자를 판정하지 않는다.
- Safety Score나 공개 별점을 제공하지 않는다.
- 채팅 전면 감시를 기본값으로 삼지 않는다.
- 응답 부재만으로 자동 신고하거나 상대방을 위험하게 판정하지 않는다.
- 서비스가 사용자의 안전을 보증한다고 표현하지 않는다.

## 미해결 문제

- Risk Signal의 구체적 분류와 심각도
- 신고 신뢰도 및 허위·보복 신고 대응
- 신호 누적에 따른 제재 기준
- 채팅 분석 범위와 개인정보 보호 경계
- Meeting Safety Check UX
- 제재 사용자의 재가입 방지
- 긴급 상황에서 서비스의 책임 범위
