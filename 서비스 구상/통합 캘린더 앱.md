# 통합 캘린더 앱 기획서

> 다른 Codex Work 스레드가 제품 설계와 구현 계획을 이어갈 수 있도록 작성한 현재 기준 문서다. 미확정 항목은 별도로 표시한다.

## 1. 문서 상태

- 상태: 기획 중, 구현 전
- 목적: 개인 사용을 위한 iOS 중심 캘린더 앱
- 사업화: 현재 목표 아님
- 구현 저장소: 아직 정하지 않음
- 앱 이름: 미정, 문서에서는 `통합 캘린더 앱`으로 지칭

## 2. 한 줄 정의

회사 Google Calendar와 개인 iCloud Calendar를 iPhone·Mac에서 함께 보고, 프리셋으로 올바른 캘린더에 빠르게 일정을 저장하는 개인용 통합 캘린더 앱.

## 3. 배경과 문제

```text
회사: Windows 노트북 → 주로 Google Calendar
집: Mac → 주로 iCloud Calendar
모바일: iPhone → 업무·개인 일정 모두 확인
```

업무 일정은 Google Calendar, 개인 일정은 iCloud Calendar에 저장될 가능성이 크다. 항상 섞어 볼 필요는 없지만 전체 일정, 충돌, 다음 일정을 함께 확인하고 싶은 순간이 있다.

기존 앱에서도 여러 캘린더를 표시할 수 있지만 계정과 캘린더를 매번 고르는 과정은 반복적이다. 본 앱은 `일정 성격을 선택하면 저장 위치가 결정되는 프리셋`으로 이 피로를 줄인다.

## 4. 목표

1. Google과 iCloud 일정을 하나의 화면에서 표시한다.
2. 업무·개인 캘린더를 빠르게 표시하거나 숨긴다.
3. 일정 생성 시 저장 위치를 명확히 보여주고 오저장을 방지한다.
4. 최대 3개 프리셋으로 저장 위치 선택을 단순화한다.
5. 일정 원본을 자체 서버에 복제하지 않고 기기 안에서 처리한다.
6. 홈 화면·잠금 화면·StandBy 위젯에서 필요한 일정을 보여준다.

## 5. 비목표

MVP에서 다음은 하지 않는다.

- 자체 회원가입, 사용자 계정, 일정 서버
- 일정 원본의 앱 DB 복제
- Google Calendar API 또는 Microsoft Graph 직접 연동
- Android·Windows·Web 클라이언트
- 사용자 간 일정 공유와 조직용 관리
- 서버 기반 AI 일정 분석
- 모든 캘린더 앱을 대체하는 범용 생산성 플랫폼

## 6. 핵심 원칙

- **원본 유지:** Google 또는 iCloud의 특정 캘린더가 원본이다.
- **저장 위치 투명성:** 프리셋을 선택해도 실제 `공급자 / 계정 / 캘린더`를 저장 전에 보여준다.
- **온디바이스 우선:** 조회, 필터, 충돌 계산, 위젯 데이터 준비를 기기에서 수행한다.
- **업무·개인 분리:** 통합 보기는 제공하되 업무 정보의 과도한 노출을 막는다.
- **시스템 재사용:** Google/iCloud 서버, OS 캘린더 동기화, `EventKit`을 사용한다.

## 7. 계정과 캘린더

일정은 계정 자체가 아니라 계정에 속한 특정 캘린더에 저장된다.

```text
iCloud 계정
├─ 개인
└─ 가족

Google 회사 계정
├─ 업무
├─ 회의
└─ 팀 공유 캘린더
```

- 공급자: iCloud 또는 Google
- 계정/Source: 시스템에 등록된 캘린더 계정
- 캘린더: 일정이 실제 저장되는 `EKCalendar`
- 일정: 특정 캘린더에 소속된 `EKEvent`

`Apple Calendar에 저장`보다 `iCloud / 개인 캘린더에 저장`이 정확하다. Apple Calendar는 관리 앱이고 iCloud Calendar가 원본 저장소다.

## 8. 계정 연결 정책

### EventKit 방식

앱 안에서 Google OAuth 로그인을 직접 받지 않는다. 사용자가 iOS 설정에 등록한 캘린더 계정을 `EventKit`으로 감지한다.

```text
iOS에 등록된 캘린더 계정
→ EventKit Source/Calendar 탐색
→ 앱에서 사용할 계정 선택
```

Google 계정이 Google Calendar 앱에만 있고 iOS 시스템 캘린더에는 등록되지 않았다면 `EventKit`으로 읽을 수 없다. 이 경우 온보딩에서 시스템 계정 추가 방법을 안내한다.

### 활성 계정 제한

- 시스템 등록 계정 수는 제한하지 않는다.
- 앱 활성 계정은 공급자 합산 최대 2개로 가정한다.
- 대표 구성은 iCloud 개인 1개 + Google 회사 1개다.
- 제한은 기술적 제약이 아니라 개인용 UX 단순화를 위한 정책이다.

`공급자별 최대 2개`인지 `전체 최대 2개`인지는 구현 전에 최종 확인이 필요하다. 현재 문서는 전체 최대 2개로 가정한다.

### 계정 표시

`EventKit`의 Source 이름이 항상 이메일이라고 가정하지 않는다. 사용자가 `회사`, `개인` 같은 별칭을 지정할 수 있게 한다. 별칭과 활성 상태만 앱 설정으로 저장한다.

## 9. 핵심 사용자 흐름

### 9.1 최초 온보딩

```text
앱 소개
→ Full Access 필요성 설명
→ 시스템 권한 요청
→ 감지된 iCloud/Google 계정 표시
→ 활성 계정 최대 2개 선택
→ 계정 별칭 설정
→ 표시할 캘린더 선택
→ 기본 저장 캘린더 설정
→ 프리셋 최대 3개 생성
→ 완료
```

권한 전 다음을 설명한다.

- 여러 캘린더를 한 화면에 표시하기 위해 필요함
- iOS는 일정 조회용 read-only 권한을 별도로 제공하지 않음
- 일정 원본을 자체 서버로 전송하지 않음
- 권한은 시스템 설정에서 철회 가능함

### 9.2 일정 통합 조회

```text
선택된 캘린더 일정 조회
→ 시간순 정규화
→ 캘린더 색상·프리셋 정보 결합
→ Today/Agenda 표시
→ App Group에 위젯용 스냅샷 저장
```

사용자는 전체 일정 보기, 업무/개인 그룹 토글, 개별 캘린더 표시·숨김, 일정 상세 보기, 시간 충돌 확인을 할 수 있다.

### 9.3 일정 생성

```text
일정 입력
→ 프리셋 선택 또는 추천
→ 실제 저장 위치 확인
→ 저장
→ EventKit
→ 시스템 캘린더 저장소
→ Google/iCloud 동기화
```

```text
제목: 팀 주간 회의
시간: 9월 8일 10:00–11:00

프리셋
[개인일정] [업무 ✓] [사이드]

저장 위치
Google · 회사 · 업무

알림: 10분 전
                           [저장]
```

저장 버튼 주변에 최종 목적지를 항상 노출한다.

## 10. 프리셋

프리셋은 일정 성격을 특정 저장 캘린더와 기본 옵션에 연결한다.

```text
개인일정 → iCloud / 개인 / 개인 캘린더
업무 → Google / 회사 / 업무 캘린더
사이드 → Google / 개인 / 사이드 프로젝트 캘린더
```

### 제한

- 활성 프리셋 최대 3개
- 작성 화면 한 줄에 모두 표시
- 표시 순서 변경 가능
- 기본 프리셋 하나 지정 가능

최대 3개는 기술적 한계가 아니라 빠른 선택과 한 줄 UI를 위한 결정이다.

### MVP 속성

- 이름, 아이콘
- 호출 키워드 목록
- 대상 계정/Source 및 대상 캘린더
- 기본 알림
- 표시 순서, 기본 여부, 활성 여부

### 키워드 추천

```text
프리셋: 업무
키워드: 업무, 회사, 회의
대상: Google / 회사 / 업무

"업무 팀 회의 내일 오전 10시"
→ `업무` 프리셋 추천
→ Google · 회사 · 업무 표시
```

MVP의 키워드는 추천 또는 선택 용도다. 사용자 확인 없이 자동 저장하지 않는다.

추천 규칙:

1. 정확한 키워드 일치 우선
2. 여러 프리셋 일치 시 후보 표시
3. 불일치 시 최근 사용 프리셋
4. 최근 사용 정보가 없으면 기본 프리셋
5. 저장 전 실제 대상 캘린더 항상 표시

후속 확장 후보: 기본 일정 길이, 반복 규칙, 장소, 공개 여부, 제목 마스킹, 시간대별 추천, 자연어 파싱.

## 11. 기능 요구사항

### FR-01 캘린더 권한

- iOS 17 이상에서 `requestFullAccessToEvents()`를 사용한다.
- `NSCalendarsFullAccessUsageDescription`에 목적을 명확히 작성한다.
- 거부, 제한, 미결정, Full Access 상태를 각각 처리한다.
- 권한 거부 시 복구 안내를 제공한다.

### FR-02 Source 및 Calendar 탐색

- `EKEventStore`에서 Source와 Calendar를 조회한다.
- iCloud와 Google 계정을 선택 대상으로 표시한다.
- 읽기 전용 캘린더는 일정 생성 대상으로 선택할 수 없게 한다.
- Source/Calendar 변경 시 설정 유효성을 다시 검사한다.

### FR-03 활성 계정

- 활성 계정 최대 2개를 선택한다.
- 계정별 별칭을 설정한다.
- 활성 계정의 캘린더만 통합 화면 후보로 사용한다.

### FR-04 캘린더 표시 설정

- 개별 캘린더를 표시하거나 숨긴다.
- 원본 색상을 기본값으로 사용한다.
- 업무/개인 그룹을 빠르게 토글한다.

### FR-05 일정 조회

- 선택 기간의 일정을 시간순으로 조회한다.
- 종일 일정과 시간 지정 일정을 구분한다.
- 반복 일정 인스턴스를 표시한다.
- 원본 계정과 캘린더를 표시한다.

### FR-06 일정 생성

- 제목, 시작/종료, 종일 여부, 반복, 알림, 메모를 입력한다.
- 프리셋 또는 직접 선택으로 대상 캘린더를 정한다.
- 저장 직전 대상 계정과 캘린더를 보여준다.
- `EKEvent.calendar`에 쓰기 가능한 `EKCalendar`를 지정해 저장한다.

### FR-07 프리셋 관리

- 프리셋을 최대 3개 생성·수정·삭제·정렬한다.
- 이름, 아이콘, 키워드, 대상 캘린더, 기본 알림을 설정한다.
- 기본 프리셋을 지정한다.
- 대상 캘린더가 사라지거나 읽기 전용이 되면 비활성화한다.

### FR-08 프리셋 추천

- 일정 제목에서 키워드를 확인한다.
- 일치하는 프리셋을 추천한다.
- 충돌하는 추천은 자동 확정하지 않는다.
- 사용자가 다른 프리셋이나 캘린더를 선택할 수 있다.

### FR-09 변경 감지

- 앱 실행 중 `EKEventStoreChanged`를 관찰한다.
- 변경 시 현재 범위의 일정을 다시 조회한다.
- 앱 활성화 시 최신 상태를 다시 조회한다.

### FR-10 위젯

- 앱이 App Group에 최소 일정 정보를 준비한다.
- WidgetKit Timeline에 다음 변화 시점을 반영한다.
- 홈 화면용 다음 일정 위젯을 우선 제공한다.
- 후속으로 잠금 화면·StandBy 위젯을 고려한다.
- 업무 일정 제목 숨김 옵션을 제공한다.

### FR-11 충돌 표시

- 서로 다른 활성 캘린더의 일정 시간이 겹치면 표시한다.
- 종일 일정은 기본적으로 시간 충돌 계산에서 제외한다.
- 경고만 제공하며 일정을 자동 변경하지 않는다.

## 12. 예외 처리

- 계정 삭제: 연결 끊김 표시 후 재선택 안내
- 캘린더 삭제: 프리셋 비활성화 후 새 대상 요청
- 읽기 전용 전환: 저장 차단 및 이유 표시
- 권한 철회: 시스템 설정 안내
- Google 동기화 지연: 로컬 저장 성공과 원격 동기화 완료를 구분
- 키워드 중복: 후보 표시 후 사용자 선택
- 반복 일정 수정: 이번 일정만/이후 일정 모두 선택
- 초대 일정: 사용자 권한에 맞는 동작만 제공
- 기본 캘린더 없음: 임의 저장하지 않고 선택 요청
- 위젯 데이터 없음: 앱 열기 또는 권한 확인 안내

## 13. 데이터 설계 초안

일정 본문은 앱 DB에 영구 복제하지 않는다. 다음 설정만 로컬에 저장한다.

```text
AccountSourcePreference
- sourceIdentifier
- provider: ICLOUD | GOOGLE | UNKNOWN
- systemTitle
- userAlias
- isEnabled
- displayOrder

CalendarPreference
- calendarIdentifier
- sourceIdentifier
- customLabel
- isVisible
- isDefaultForNewEvent

CalendarPreset
- id
- name
- icon
- keywords: [String]
- targetSourceIdentifier
- targetCalendarIdentifier
- defaultAlertMinutes
- displayOrder
- isDefault
- isEnabled
```

주의:

- EventKit 식별자의 영속성과 계정 재등록 상황을 검증한다.
- 저장된 식별자가 사라질 수 있음을 전제로 한다.
- 위젯 스냅샷은 제한된 임시 데이터로 취급한다.
- 참석자, 메모, 위치 등 불필요한 정보를 위젯 저장소에 넣지 않는다.

## 14. 기술 구조

```text
Google Calendar 서버 ─┐
                      ├→ iOS/macOS 시스템 캘린더 저장소
iCloud Calendar ──────┘                ↓
                                     EventKit
                                        ↓
                    ┌───────────────────┴───────────────────┐
                    ↓                                       ↓
             SwiftUI App                         App Group Snapshot
                                                            ↓
                                                      WidgetKit
```

- Google/iCloud: 원본 저장 및 기기 간 동기화
- iOS/macOS: 계정 동기화와 로컬 캘린더 저장소
- EventKit Adapter: Source, Calendar, Event 조회·저장
- App: 필터, 프리셋, 충돌 계산, 작성 UX
- Widget Extension: 준비된 최소 데이터 표시

### 자체 서버가 필요 없는 이유

클라이언트가 서버 역할을 하는 것이 아니다. 기존 서버와 OS 동기화 계층을 재사용한다.

```text
앱 저장 → EventKit → iOS 캘린더 저장소
→ iOS가 Google/iCloud에 동기화 → 다른 기기에 반영
```

서버는 직접 Google API 연동, webhook, 앱 자체 계정/DB, Android·Web·Windows, 사용자 간 공유, 서버 알림·AI가 필요할 때 검토한다. 현재 범위에는 필요 없다.

## 15. 개인정보 및 보안

- 캘린더 내용은 기기 안에서 처리한다.
- 일정 제목, 참석자, 위치, 메모를 자체 서버로 보내지 않는다.
- 불필요한 분석 SDK를 넣지 않는다.
- 위젯에는 필요한 최소 필드만 전달한다.
- 업무 일정 제목을 `업무 일정`으로 마스킹할 수 있게 한다.
- 잠금 화면 위젯은 보수적인 정보 표시를 기본값으로 검토한다.
- 개인정보 처리방침에 수집 여부와 온디바이스 처리를 명시한다.

회사 MDM 또는 Google Workspace 정책이 시스템 캘린더 연결을 금지할 수 있다. 앱은 이를 우회하지 않는다.

## 20. MVP 완료 기준

- iCloud 1개와 Google 1개를 활성 계정으로 선택한다.
- 선택 캘린더 일정이 하나의 Today 화면에 표시된다.
- `개인일정`, `업무` 프리셋을 서로 다른 캘린더에 연결한다.
- 제목 키워드로 프리셋이 추천되고 사용자가 변경할 수 있다.
- 목적지가 저장 전 명확히 표시된다.
- 일정이 선택한 원본 캘린더에 저장된다.
- 외부 변경이 앱 재활성화 또는 변경 알림 후 갱신된다.
- 위젯에 다음 일정이 표시된다.
- 제목 마스킹 시 실제 업무 제목이 위젯에 노출되지 않는다.
- 계정·캘린더 삭제와 권한 철회 시 복구 안내가 표시된다.
- 자체 백엔드 없이 동작한다.
